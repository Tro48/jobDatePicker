# Архитектура

## Стек

| Решение | Почему |
| --- | --- |
| React Native через Expo, SDK 57 | Локально нет JDK и Android SDK. Сборка APK уходит в облако EAS, на телефоне ставится dev build, разработка идёт с горячей перезагрузкой по Wi-Fi. |
| Dev build, не Expo Go | Нужен свой нативный код: будильник на AlarmManager в Expo Go невозможен. |
| TypeScript, strict | Домен целиком типизирован, id смен и графиков проверяются на старте. |
| expo-router | Файловая навигация, табы из коробки, дип-линки для будильника (`jobdatepicker://day/2026-09-14`). |
| Zustand + react-native-mmkv 4 | Данных мало: настройки, справочник смен, правки по дням, выплаты. MMKV синхронный, читается на старте без мигания пустым экраном. Версия 4 работает через Nitro и требует dev build — в Expo Go её нет. |
| Свой компонент календаря | Готовые библиотеки придётся ломать под две темы, буквы-маркеры и озвучку TalkBack. Месячная сетка — 200 строк, дешевле написать, чем перебарывать. |
| Свои утилиты дат вместо date-fns в домене | Домен не тянет зависимостей и запускается в голом Node. Для локализованных названий месяцев на экранах хватит `Intl`. |

## Слои

```
app/            маршруты expo-router, только композиция экранов
src/features/   экраны и их локальные компоненты
src/ui/         переиспользуемые компоненты, хук темы
src/theme/      палитра, типографика, отступы
src/data/       хранилище (MMKV), репозитории, миграции схемы
src/domain/     чистая логика: графики, часы, деньги. Не знает про React
modules/shift-alarm/  нативный модуль будильника (Kotlin, Expo Modules API)
```

Правило одно: `src/domain/` не импортирует ничего из React Native. За счёт
этого вся арифметика графиков и денег покрыта тестами, которые бегут за 100 мс
в обычном Node, без эмулятора и без сборки.

## Хранилище

Один MMKV-инстанс, значения — JSON под стабильными ключами:

| Ключ | Содержимое |
| --- | --- |
| `schema.version` | номер версии, для миграций |
| `settings.schedule` | `ActiveSchedule`: id пресета, паттерн, дата первой смены |
| `settings.payroll` | валюта, правила выплат |
| `settings.alarms` | список будильников: время, повтор, мелодия, отсрочка |
| `settings.appearance` | тема: системная / светлая / тёмная |
| `overrides` | правки по дням, объект `{ "2026-09-03": DayOverride }` |
| `payments` | массив `PaymentRecord` |

Паттерн графика хранится копией, а не только по `presetId`. Иначе правка
пресета в будущей версии задним числом перепишет уже прожитые месяцы.

Справочник смен, наоборот, **не хранится**: он задан кодом. Снимок из старой
сборки перекрывал новые поля — так у отпуска пропал признак многодневности, и
карточка дня перестала спрашивать количество дней. Правило простое: в хранилище
уходят данные пользователя, справочники живут в коде. Версия схемы поднята до 2,
миграция подставляет справочник из кода поверх любого старого снимка.

Объём: правок и выплат — десятки в год, всё держится в памяти. SQLite здесь
был бы лишним; репозитории в `src/data/` изолируют хранилище на случай, если
данных станет заметно больше.

## Что считается на лету, а что хранится

Календарь не материализуется. Хранятся только график, дата первой смены и
ручные правки; конкретный день вычисляется функцией `resolveDay`. Поэтому смена
графика или сдвиг даты первой смены мгновенно перерисовывает всю историю и не
требует пересчёта базы.

Обратная сторона: изменив дату первой смены, пользователь меняет и прошлое.
Ручные правки при этом остаются на своих датах — они привязаны к дате, а не к
позиции в цикле.

## Фактические версии

Expo SDK 57.0.18, React Native 0.86.3, React 19.2.3, TypeScript 6.0 в строгом
режиме. Новая архитектура и edge-to-edge в SDK 57 включены всегда и в
`app.json` не настраиваются.

Два места, где пришлось вмешаться в зависимости:

- `react-dom` пинится через `overrides` на 19.2.3. `expo-router` тянет
  `react-dom@19.2.8`, которому нужен `react ^19.2.8`, а Expo пинит React 19.2.3.
  Это веб-ветка роутера, на Android она не исполняется, но без пина дерево
  невалидно и любая следующая установка падает с ERESOLVE.
- `react-native-nitro-modules` записан прямой зависимостью, хотя приходит
  транзитивно из `react-native-mmkv` — чтобы автолинковка не зависела от того,
  как npm разложит дерево в следующий раз.

- `react-native-reanimated` и `react-native-worklets` записаны точными
  версиями 4.5.1 и 0.10.1 — это канон SDK 57 из `bundledNativeModules.json`.
  Без пина npm ставил reanimated 4.6.0, тянувший worklets 0.12.1, и облачная
  сборка падала на компиляции C++:
  `no member named 'executeSync' in 'worklets::WorkletRuntime'`.
  `expo-modules-core@57.0.14` собран под API worklets до 0.10, и более свежего
  патча Expo для SDK 57 не существует.

Отдельный вывод из этой поломки: `expo-doctor` проходил 21 проверку из 21 и до
пина, и после. Рассинхрон нативных версий он не ловит — это выясняется только
компиляцией в облаке. Локальные проверки закрывают JS, но не нативную часть.

## Импорты и алиасы

Внутри `src/` и `app/` используется алиас `@/` на папку `src`. Файлы доменного
слоя импортируют друг друга с расширением `.ts` — этого требует запуск тестов в
голом Node через `--experimental-strip-types`. Чтобы то же самое понимал `tsc`,
в `tsconfig.json` включён `allowImportingTsExtensions`; Metro такие пути
резолвит без дополнительной настройки.
