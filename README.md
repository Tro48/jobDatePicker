# jobDatePicker

Календарь сменного графика для Android. Выбираешь готовый график и дату первой
смены — календарь заполняется сам, на годы вперёд и назад. Поверх графика
вносятся ручные правки (отпуск, больничный, подработка), считаются
отработанные часы и деньги, а перед сменой звонит настоящий будильник — не
уведомление, которое Android волен задержать на двадцать минут.

Приложение для себя, в маркет не выкладывается. APK ставится вручную.

## Что умеет

- **Календарь смен.** Десять готовых графиков: 2/2, 3/3, день–ночь–отсыпной–выходной,
  сутки через трое, пятидневка, 6/1. Дневные и ночные смены различаются
  и цветом, и буквой в клетке. Уже отработанные смены приглушены, а день, где
  часы разошлись с графиком, помечен точкой: зелёной при переработке, красной
  при недоработке. Под сеткой — итог месяца той же точкой: «Переработка 6 ч».
- **Правки по дням.** Отпуск и больничный ставятся отрезком нужной длины,
  подработка и внеплановый выходной — одним днём. Правка видна в календаре и
  учитывается везде, где считаются часы. Сводка за месяц показывает смены и
  часы дробью — сколько уже отработано из запланированного.
- **Деньги.** Полученные аванс, зарплата, отпускные и больничные вносятся
  руками; приложение выводит из них ставку за час и за смену, показывает сводку
  за месяц и за год и напоминает, когда ждать следующую выплату. Отпускные и
  больничные в ставку не идут — иначе месяц с отпуском показал бы её вдвое
  выше настоящей.
- **Будильник по графику.** Звонит только в рабочие дни и знает, что перед
  ночной сменой вставать надо в другое время, чем перед дневной. Работает
  поверх экрана блокировки, переживает «Не беспокоить» и перезагрузку.
- **Обновления по воздуху.** Правки экранов и расчётов приезжают сами. О том,
  что приехало, календарь сообщает одной строкой сверху: нажать — откроется
  список изменений, закрыть — больше не покажется. Когда меняется нативная
  часть, та же строка говорит, что вышла новая сборка, а кнопка скачивания APK
  и ручная проверка живут в настройках.

## Состояние: бета

Приложение написано целиком и работает на устройстве, но пользователь у него
пока один, и на длинной дистанции оно не проверено. Что это значит на практике:

- Схема хранилища ещё может меняться. Миграции пишутся, данные при обновлении
  сохраняются, но обещать этого на будущее нельзя.
- Нативная часть будильника проверяется только вживую: локально Kotlin не
  компилируется, тестов на неё нет.
- Оболочки Xiaomi, Huawei, Oppo, Vivo и Samsung агрессивно выгружают фоновые
  приложения. Чтобы будильник звонил, автозапуск и снятие ограничений батареи
  включаются руками в настройках телефона — выдать себе такое разрешение
  приложение не может.
- Собирается и проверяется только под Android. iOS не поддерживается.

## Стек

| Слой       | Чем сделано                                                                    |
| ---------- | ------------------------------------------------------------------------------ |
| Каркас     | Expo SDK 57, React Native 0.86, React 19                                       |
| Навигация  | expo-router, четыре вкладки и шторки поверх них                                |
| Состояние  | zustand + persist                                                              |
| Хранилище  | react-native-mmkv (синхронное чтение — состояние поднимается до первого кадра) |
| Анимации   | react-native-reanimated                                                        |
| Будильник  | свой нативный модуль на Kotlin, `AlarmManager.setAlarmClock()`                 |
| Обновления | expo-updates, канал на EAS                                                     |
| Язык       | TypeScript, строгий режим                                                      |
| Проверки   | ESLint, Prettier, node:test для домена, jest + Testing Library для экранов     |

Тестов два набора, и это не дублирование. Доменный (`npm run test:domain`)
бежит в голом Node без сборщика — сама возможность так его запустить и есть
проверка того, что расчёты не завязаны на React. Второй (`npm run test:ui`)
поднимает настоящий React Native через jest и проверяет экраны, хуки и
хранилище с миграциями. Файлы различаются по имени: `*.test.ts` — домен,
`*.spec.tsx` — всё остальное.

Расчёты графика, часов и денег живут в `src/domain/` и не импортируют ни React,
ни React Native: это чистые функции над «гражданскими датами» (`YYYY-MM-DD`) и
целыми сутками. Арифметика по миллисекундам сознательно не используется — в
ночь перевода часов сутки не равны 24 часам, а график 2/2 обязан остаться 2/2.

## Установка

Готовый APK лежит в
[релизах](https://github.com/Tro48/jobDatePicker/releases/latest). Скачать,
разрешить установку из неизвестных источников, поставить поверх текущей версии —
данные сохранятся.

После установки стоит зайти в настройки телефона и разрешить приложению
автозапуск и работу без ограничений батареи, иначе оболочка выгрузит его и
будильник не зазвонит.

## Разработка

Нужен Node 22 и бесплатный аккаунт [Expo](https://expo.dev). JDK и Android SDK
локально не нужны — APK собирается в облаке EAS.

```bash
npm install
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile development
```

Готовый APK ставится по ссылке из вывода команды. Дальше разработка идёт с
горячей перезагрузкой:

```bash
npm start          # expo start --dev-client
```

Пересобирать APK нужно только при добавлении нативного кода или новых нативных
зависимостей — правки JavaScript прилетают на телефон сами.

Отладочное и рабочее приложения различаются идентификатором пакета и стоят на
телефоне рядом, не затирая данные друг друга. Вариант выбирается переменной
`APP_VARIANT`.

### Проверки

```bash
npm run lint            # ESLint
npm run format:check    # Prettier, только проверка; npm run format — с правкой
npm run typecheck       # tsc --noEmit
npm test                # оба набора тестов подряд
npm run test:domain     # 128 тестов доменного слоя и чистой арифметики
npm run test:ui         # 24 теста экранов, хуков и хранилища
npm run check:contrast  # 192 проверки контраста по WCAG
npx expo-doctor         # конфигурация проекта
```

Всё это работает без Android SDK и без телефона: доменный слой не зависит от
React Native, а Node 22 исполняет TypeScript напрямую.

Перед пушем то же самое прогоняет хук `.husky/pre-push` — узнать о красных
тестах на своей машине за полминуты дешевле, чем через пять минут в Actions.
Разъехавшееся форматирование он правит сам, но пуш при этом останавливает:
правки остаются в рабочем каталоге, и в уходящий коммит они не попадают, пока
их туда не добавишь.

Зелёные проверки **не** означают, что APK соберётся: они закрывают только
JavaScript. Рассинхрон нативных версий выясняется исключительно компиляцией в
облаке.

### Ветки и CI

Работа идёт в `dev`, в `main` попадает то, что готово к выкатке.

| Событие                        | Что происходит                                             |
| ------------------------------ | ---------------------------------------------------------- |
| пуш в `dev`, любой пул-реквест | типы, тесты, контраст, `expo-doctor`, сборка JS-бандла     |
| мерж в `main`                  | те же проверки, подъём версии, затем развилка по отпечатку |

Развилка решает, чем доставлять. Правки экранов и расчётов уезжают обновлением
по воздуху за секунды. Если же изменилась нативная часть — модуль будильника,
нативные зависимости, разрешения, иконка, заставка, — по воздуху её не
доставить, и вместо обновления встаёт в очередь сборка APK.

Отличает одно от другого отпечаток: `expo-updates fingerprint:generate` даёт
отпечаток текущего кода, а отпечаток уже выпущенной сборки лежит в `android.json`
последнего релиза — в том самом файле, который читает само приложение. Разошлись
— нужна сборка.

**Лимит сборок EAS — 15 в месяц на платформу.** Поэтому сборка и привязана к
отпечатку, а не к самому мержу: за месяц нативная часть меняется несколько раз,
а мержей заметно больше. Сборку можно запустить и руками — workflow «Сборка
Android», с выбором профиля.
