# jobDatePicker

Календарь сменного графика для Android: выбираешь график и дату первой смены —
календарь заполняется сам. Поверх графика вносятся ручные правки, считаются
часы и деньги, срабатывает будильник перед сменой.

В маркет не выкладывается, сборка для себя.

## Проверки

```bash
npm run test:domain     # 52 теста доменного слоя
npm run check:contrast  # 60 проверок контраста по WCAG
npm run typecheck       # tsc --noEmit
npx expo-doctor         # 21 проверка конфигурации проекта
```

Первые три работают без Android SDK и без телефона: доменный слой не зависит от
React Native, а Node 22 исполняет TypeScript напрямую.

## Ветки и CI

Работа идёт в `dev`, в `main` попадает то, что готово к сборке.

| Событие | Что происходит |
| --- | --- |
| пуш в `dev`, любой пул-реквест | `.github/workflows/checks.yml`: типы, тесты, контраст, `expo-doctor`, сборка JS-бандла |
| мерж в `main` | те же проверки, затем постановка APK в очередь EAS |

Проверки описаны один раз: `build.yml` вызывает `checks.yml` через
`workflow_call`, а не копирует шаги.

Чтобы это заработало, нужно два действия помимо кода:

1. Завести remote на GitHub — сейчас репозиторий только локальный.
2. Положить в секреты репозитория `EXPO_TOKEN` из expo.dev → Access tokens.

**Лимит сборок — 15 в месяц на платформу.** Каждый мерж в `main` съедает одну,
и отладка нативных зависимостей съедает их быстрее всего: локально нативную
часть проверить нечем. Поэтому `main` — редкое событие, а не рабочая ветка.
Если мержи участятся, триггер стоит сменить на тег или оставить только ручной
`workflow_dispatch`.

Зелёный CI **не** означает, что APK соберётся: локальные проверки закрывают
только JavaScript. Рассинхрон нативных версий не ловит даже `expo-doctor` —
он выясняется исключительно компиляцией в облаке.

## Запуск на телефоне

Локально нет JDK и Android SDK, поэтому APK собирается в облаке EAS.

```bash
npx eas-cli@latest login                                   # нужен бесплатный аккаунт Expo
npx eas-cli@latest build --platform android --profile development
```

Пакет называется `eas-cli`, хотя команда внутри него — `eas`. Через `npx`
нужно писать полное имя пакета, иначе npm не найдёт, что запускать.

Готовый APK ставится на телефон по ссылке из вывода команды. Дальше разработка
идёт с горячей перезагрузкой:

```bash
npm start              # expo start --dev-client
```

Пересобирать APK нужно только при добавлении нативного кода или новых нативных
зависимостей. Правки JavaScript прилетают на телефон сами.
